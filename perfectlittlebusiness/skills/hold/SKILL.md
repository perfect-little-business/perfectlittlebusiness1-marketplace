# /hold — Hold On To This

## Purpose

You cannot listen to a podcast, read a book or sit through a conversation without
connecting something in it to your own work. A story a guest told. A line someone
said. An idea you know exactly how you would use. And then you have nowhere to put
it, so it is gone.

`/hold` is the somewhere. You say "hold on to this" and tell it the thing. It files
the thing, keeps your own words about what you would connect it to, and gets out of
the way. Months later, when you are outlining an episode or drafting a post, the
held entries that fit come back to you.

You never have to decide up front what it is for. That is the point.

## When To Use

- You heard a story you would tell differently, and better, and know where it fits
- A quote or a line you want to keep
- An idea for an episode, a post, a newsletter, an offer, a talk
- Something you noticed that connects to your work and you do not want to lose
- Any voice memo or note that says "hold on to this" or "remember this for later"

Do not use `/hold` for insights about your own business (that is `/learn`), for
decisions (that is `/decide`), or for client wins (that is `wins.md`). `/hold` is for
raw material you want to use later, not for things you have learned.

## Where it lives

```
brain/inspiration/
├── README.md              how this folder works
├── _INDEX.md              one line per entry, regenerated by the script, never hand-edited
└── YYYY-MM-DD-slug.md     one file per held entry
```

The folder is created the first time `/hold` runs if `/setup` did not create it.

## Execution Instructions

`/hold` has three verbs. With no verb, it captures.

### Capture: `/hold [the thing]`, or `/hold` alone, or a voice memo

**Step 1: Get the thing.**

- If the user typed `/hold` with content, use it.
- If the user typed `/hold` alone, ask: "What do you want to hold on to?" and wait.
- If the user points at a voice memo, a Granola note or a pasted transcript, read
  it. One memo can hold several things; split it into one entry each and say how
  many you found before writing anything.

**Step 2: Keep their words.**

Two fields carry the value, and both are the user's words, quoted, never
paraphrased:

- **The thing itself**, as they told it. If they told a story in three sentences,
  keep the three sentences. Do not tighten it, do not tidy it, do not add facts
  they did not say. If the story is from a podcast or a book, record the source
  they named and nothing more.
- **What they would connect it to.** This is the field that pays off later. The
  story is easy to find again; the connection is what gets forgotten. If they said
  "I know exactly what I would connect it to" and did not say what, **ask for the
  one sentence before filing**: "What would you connect it to? One sentence in
  your words is enough." If they cannot say yet, file it with the field marked
  `(not yet said)` rather than inventing one.

**Step 3: Read the brain for tags, never invent a vocabulary.**

Read `brain/` looking for the business's own content taxonomy or pillar list. It is
usually in `brain/reference/` (a file with "taxonomy", "pillars" or "content" in
the name) or in `CLAUDE.md`. If one exists, tag the entry with its pillars, using
its exact names. If none exists, leave `pillars` empty and tag nothing. A story
bank with made-up categories stops being trusted, so the taxonomy comes from the
business or it does not exist.

Pick a `kind`: `story`, `quote`, `idea` or `observation`. Pick the one that fits;
do not add kinds.

**Step 4: Show the entry and confirm.**

Show the drafted file, then ask one question: "Hold it? Or change anything?" One
round of edits at most. Do not ask three questions in a row; capture has to be
fast or it does not happen.

**Step 5: Write, then rebuild the index.**

Write `brain/inspiration/YYYY-MM-DD-slug.md` in the format below. Then rebuild the
index:

```
python3 "${CLAUDE_PLUGIN_ROOT}/skills/hold/scripts/hold_index.py"
```

(from the project root; it finds `brain/inspiration/` by itself. The script lives
next to this skill at `scripts/hold_index.py`, so if the variable is not set,
run it by that path from the skill's folder with `--brain <project>/brain`). If the script
cannot run in this environment, append the entry's line to `_INDEX.md` by hand in
the same shape as the existing lines and say that you did.

**Step 6: Return to work.**

Output: "Held: {title}. Back to what we were doing." Nothing else.

### Stamp as used: `/hold used {entry} in {where}`

When a held entry ships (an episode, a post, a newsletter, a talk), stamp it so it
is never repeated by accident and so the record shows which stories carried which
subjects. Set `status: used` and add the place to `used_in`, then rebuild the index.
Say: "Stamped: {title}, used in {where}."

Drafting skills that pull from this folder should stamp the entry they used as
part of finishing the draft. If you drafted from a held entry, stamp it.

### Find what fits: `/hold find {topic}`

Read `_INDEX.md`, then open every entry whose index line or text plausibly fits the
topic. Return the two to four best fits, each as: the title, the kind, the source,
and the user's own connection sentence quoted. Held entries first, used entries
after, marked as used. If nothing fits, say so in one line; never pad with weak
matches.

The script can do the first pass:

```
python3 "${CLAUDE_PLUGIN_ROOT}/skills/hold/scripts/hold_index.py" --find "pricing, saying no, scope"
```

## Entry format

```markdown
---
held: 2026-09-12
kind: story
source: "Conan O'Brien's podcast, a guest's story"
pillars: []
status: held
used_in: []
---
# {A title the user would recognize, six words or fewer}

## The thing itself
{Their words. The story, the quote, the idea, as told.}

## What I would connect it to
> {Their words, quoted. Or: (not yet said)}

## Notes
{Anything else they said about it. Delete this section if empty.}
```

`held` is the capture date. `used_in` is a list of places, in the user's own naming
("EP 152", "newsletter 2026-10-03"). `status` is `held` or `used`, nothing else.

## Notes for Claude Executing This Skill

- **Speed over completeness.** A held entry with a good title, the thing itself and
  the connection is complete. Do not interview.
- **Their words, every time.** The moment you paraphrase the connection, the entry
  loses the thing that made it worth keeping. Quote.
- **Never add facts to a story.** If they said "the Matt Groening story about the
  15-minute episodes," that is the whole record. Do not look the story up and fill
  it in. They know the story; the entry is a handle, not an encyclopedia.
- **One home.** Do not also write the entry into `learnings.md`, `wins.md` or
  `MEMORY.md`. If it is genuinely also a learning, they will say so.
- **The index is generated.** Never hand-edit `_INDEX.md` when the script is
  available. If you appended by hand because the script could not run, say so, so
  the next session rebuilds it.
- **Reading the folder from other skills.** `/draft-social`, `/ask` and any episode
  or newsletter prep should read `brain/inspiration/_INDEX.md` when it exists and
  offer the held entries that fit. That is how a story from ten months ago comes
  back at the right moment without anyone remembering to look.
